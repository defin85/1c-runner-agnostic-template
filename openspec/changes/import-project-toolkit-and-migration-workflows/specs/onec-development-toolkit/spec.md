## ADDED Requirements

### Requirement: Клиент 1С для визуальной проверки запускается штатной обёрткой

Шаблон MUST поставлять навык `1c-run-client` и обёртки `scripts/platform/run-client.sh` и `run-client.ps1`. Обёртка MUST открывать базу runtime-профиля в отдельном Xpra-сеансе своего `--run-root`, брать пароль только из `infobase.auth.passwordEnv` профиля и заменять его на `***` в выводе и файлах запуска. Она MUST позволять сделать снимок экрана, нажать клавишу или кликнуть и закрыть клиент; эти команды MUST действовать только на дисплей и процесс своего `--run-root`. Запуск MUST наблюдаться общим адаптером из capability `long-operation-observation`. Навык MUST запрещать прямой запуск `1cv8`, использование `xpra`/`xdotool` на чужом дисплее и передачу пароля в аргументах `db-run`.

#### Scenario: Открытие формы для проверки

- **WHEN** агент открывает обработку по навигационной ссылке через `run-client.sh` и делает снимок экрана
- **THEN** клиент работает в собственном Xpra-сеансе, а ответ команды содержит путь к PNG-снимку
- **AND** пароль отсутствует в выводе обёртки, `observation.jsonl` и `summary.json`

#### Scenario: Служебная обработка перестала обновлять прогресс

- **WHEN** обработка запущена с `--wait --idle-timeout <сек> --progress-file <файл>`, и файл прогресса после первой записи не менялся дольше заданного времени
- **THEN** обёртка сохраняет снимок `<run-root>/screenshots/idle-timeout.png`, закрывает свой клиент и возвращает код 125 со статусом `idle-timeout`

### Requirement: Проверка BSL выполняется в точном контуре конфигурации

Навык `1c-check-bsl` и сценарий `scripts/platform/check-cf-modules.sh` MUST проверять изменённые модули в указанной ИБ, на её версии платформы и в режиме совместимости её конфигурации. Успешная проверка в другой конфигурации или другом режиме совместимости MUST NOT считаться доказательством для целевой конфигурации.

#### Scenario: Изменён модуль конфигурации со старым режимом совместимости

- **WHEN** разработчик проверяет модуль, в котором используется функция, недоступная в режиме совместимости целевой конфигурации
- **THEN** `check-cf-modules.sh` возвращает ненулевой код и имя модуля с ошибкой компиляции
- **AND** результат проверки содержит версию платформы и режим совместимости целевой ИБ

#### Scenario: Проверка ограничена выбранными модулями

- **WHEN** сценарию переданы пути двух модулей
- **THEN** платформенная проверка загружает и компилирует только эти модули и указывает их в результате

### Requirement: Отсутствие авторитетной проверки фиксируется явно

Если `bsl-analyzer` и платформенная проверка недоступны, инструменты шаблона MUST фиксировать результат `синтаксис: не проверен`. Тесты шаблона MUST NOT выводить синтаксис или поведение BSL из совпадения строк, regex или разбора текста модуля.

#### Scenario: Анализатор недоступен

- **WHEN** `bsl-analyzer` не отвечает и платформенная ИБ не указана
- **THEN** итог проверки содержит `синтаксис: не проверен`, а не успешный статус

### Requirement: Метаданные меняются через CLI модели объектов

Шаблон MUST поставлять CLI метаданных (`scripts/python/metadata*.py`) с командами чтения и изменения XML-выгрузки конфигурации и расширения через модель объектов, включая элементы управляемых форм и табличные макеты. Навык `metadata-use` MUST направлять агента к этому CLI вместо ручного редактирования XML. Результат изменения MUST подтверждаться авторитетной проверкой платформы или `metadata verify`, а не тестом CLI.

#### Scenario: Добавление реквизита объекта

- **WHEN** агент добавляет реквизит справочника командой CLI
- **THEN** CLI изменяет только XML этого объекта и сообщает изменённые файлы
- **AND** итоговая выгрузка загружается платформенной обёрткой без ошибок структуры

#### Scenario: Некорректная команда не портит выгрузку

- **WHEN** команда CLI получает несуществующий объект
- **THEN** CLI завершается с ошибкой и не изменяет ни одного файла

### Requirement: Обычные формы и внешние обработки адаптируются по регламенту

Шаблон MUST поставлять конвертацию обычных форм (`ordinary_form_conversion.py`), работу с контейнерами `v8unpack`, навыки `ordinary-form-workflow`, `prepare-external-artifact`, `cfe-form-workflow`, `v8unpack` и регламент `docs/agent/ordinary-form-conversion-runbook.md`. Регламент MUST требовать проверки каждого изменённого BSL-модуля EPF/ERF через `bsl-analyzer` с точным подключением целевой ИБ. Успешная сборка EPF/ERF MUST NOT считаться проверкой синтаксиса.

#### Scenario: Сборка EPF прошла, анализатор недоступен

- **WHEN** EPF собран успешно, а проверка модулей анализатором не выполнена
- **THEN** итог передачи кандидата содержит `синтаксис: не проверен`

### Requirement: Стандарты разработки доступны из локального кеша

Шаблон MUST поставлять `scripts/tools/v8std-fetch <std-id-or-url>` и `scripts/tools/v8std-search <query>`. Кеш стандартов MUST храниться вне Git: по умолчанию в `.artifacts/v8std` или по пути из `V8STD_CACHE_ROOT`. Инструменты MUST NOT копировать тексты стандартов в отслеживаемые файлы репозитория.

#### Scenario: Загрузка стандарта

- **WHEN** разработчик выполняет `v8std-fetch` с номером стандарта
- **THEN** страница сохраняется в кеш вне Git, и `git status` не показывает новых файлов

### Requirement: Поиск по репозиторию следует единому регламенту

Шаблон MUST поставлять `docs/agent/repository-search-runbook.md`. Регламент MUST разделять семантический индекс репозиторного контекста (корень с исключением `src/**`) и отдельные индексы исходников конфигураций и расширений. Он MUST задавать порядок: семантический поиск → `rg` → `rg --files` → прямое чтение.

#### Scenario: Поиск модуля конфигурации

- **WHEN** агент ищет процедуру в исходниках конфигурации
- **THEN** регламент направляет его в индекс точного корня конфигурации, а не в индекс корня репозитория
