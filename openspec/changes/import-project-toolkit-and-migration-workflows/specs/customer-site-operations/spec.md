## ADDED Requirements

### Requirement: Модуль площадки материализуется только явной командой

Шаблон MUST поставлять заготовку модуля в `automation/optional/customer-site-operations/`. Команда `make optional-module-init MODULE=customer-site-operations` MUST копировать заготовку в project-owned пути `infra/site/`, `docs/infra/site/` и `.agents/skills/site-*`. Если хотя бы один целевой путь уже существует, команда MUST завершиться с ошибкой без изменений.

#### Scenario: Первая инициализация

- **WHEN** в проекте нет целевых каталогов модуля и выполняется команда инициализации
- **THEN** каталоги созданы из заготовки, а пути зарегистрированы как project-owned

#### Scenario: Повторная инициализация

- **WHEN** каталог `infra/site/` уже существует
- **THEN** команда возвращает ненулевой код, и ни один файл проекта не изменён

### Requirement: Поставляемые материалы площадки обезличены

Заготовка модуля и общие сценарии оператора MUST NOT содержать имена серверов, домены, IP-адреса, CIDR, UUID баз и кластеров, имена баз и учётные записи заказчика, итоги операций по базам, пути хоста разработчика. Сведения о площадке MUST задаваться только project-owned профилями `*.json`, которые не отслеживаются Git. Их примеры с вымышленными значениями MUST иметь суффикс `.example.json`.

#### Scenario: Проверка публикационной границы

- **WHEN** запускается `tests/smoke/customer-site-deidentified.sh`
- **THEN** проверка завершается ошибкой, если в поставляемых путях модуля найден IPv4-адрес, UUID вне закреплённого списка фикстур или имя из списка известных проектных идентификаторов

### Requirement: Ввод команды в удалённый терминал проверяется до выполнения

Инструмент ввода команды MUST:

- принимать одну ASCII-строку длиной не более 4096 символов;
- отклонять строки с `exit`, `logout`, `exec` и символами вне ASCII;
- набирать строку в заданный DISPLAY без нажатия Enter;
- сверять набранную строку со снимком экрана или через буфер удалённого сеанса.

Enter MUST отправляться отдельной командой после сверки.

#### Scenario: Строка содержит запрещённую команду

- **WHEN** оператор передаёт строку, содержащую `exit`
- **THEN** инструмент отказывает до набора и ничего не вводит

#### Scenario: Набранная строка отличается от исходной

- **WHEN** сверка показывает расхождение набранной строки с исходной
- **THEN** инструмент сообщает расхождение и не отправляет Enter

### Requirement: Передача файла на сервер подтверждается SHA-256 до установки

Инструмент передачи файла MUST формировать команды из фрагментов gzip+base64 длиной не более 240 символов. Итоговая команда MUST вычислять SHA-256 собранного файла на удалённом сервере и выполнять `sudo -n install` с заданными владельцем и правами только при совпадении с ожидаемой суммой.

#### Scenario: Сумма не совпала

- **WHEN** SHA-256 собранного файла на сервере отличается от ожидаемого
- **THEN** установка не выполняется, и команда выводит `sha256_match=0`

#### Scenario: Сумма совпала

- **WHEN** SHA-256 совпадает
- **THEN** файл установлен с заданными владельцем и правами, и команда выводит `sha256_match=1`

### Requirement: Серверные обёртки работают на системном Python площадки

Серверные обёртки модуля (`site-rac`, включая включение и отключение регламентных заданий базы `jobs-on`/`jobs-off`; `site-ibcmd`; golden, архив и восстановление DT, создание согласованной копии базы из DT и удаление неудачной копии; управление технологическим журналом; подготовка офлайн-лицензирования) MUST использовать только стандартную библиотеку Python. Они MUST запускаться на Python 3.7 и новее. Изменяющие операции MUST быть отделены от read-only команд и MUST отказывать, если цель не указана явно в профиле разрешённых баз.

#### Scenario: Запуск на старом системном Python

- **WHEN** обёртка запускается интерпретатором Python 3.7 без сторонних пакетов
- **THEN** read-only команда `info` выполняется без ошибок импорта

#### Scenario: Изменение неразрешённой базы

- **WHEN** изменяющей команде передано имя базы, отсутствующее в профиле разрешённых баз
- **THEN** обёртка возвращает отказ `Refused` до обращения к кластеру или СУБД

### Requirement: VDI-клиент работает в изолированном сеансе Xpra

Навык `site-vdi-xpra` и сценарий запуска клиента MUST:

- запускать VDI-клиент в отдельном DISPLAY Xpra без буфера обмена и передачи файлов;
- удалять из окружения клиента переменные `*_proxy` и `WAYLAND_DISPLAY`;
- хранить файл подключения, журналы и снимки экрана только в приватном runtime-каталоге с правами 0700;
- не выводить содержимое файла подключения.

#### Scenario: Запуск с прокси в окружении

- **WHEN** в окружении оператора заданы переменные `https_proxy` и `WAYLAND_DISPLAY`
- **THEN** в окружении процесса VDI-клиента этих переменных нет, а `DISPLAY` равен заданному

### Requirement: Восстановление доступа к ИБ требует резервной копии и проверки возврата

Если модуль поставляет обёртку восстановления доступа через служебные таблицы СУБД, обёртка MUST выполнять шаги в таком порядке:

1. `backup` — полная копия базы или копия затрагиваемых таблиц и строк с SHA-256.
2. `hide` — только после сверки копии с живыми данными внутри транзакции.
3. `restore` — возврат исходных данных.
4. `verify` — выдаёт `BACKUP_RESTORE_VERIFIED` только при двустороннем совпадении копии и таблицы.

Регламент MUST указывать, что метод не является документированным API 1С и проверен только на указанных версиях платформы и СУБД.

#### Scenario: Попытка скрыть таблицу без копии

- **WHEN** выполняется `hide` без предшествующего успешного `backup` для этой базы
- **THEN** обёртка отказывает, и служебные таблицы не изменены
