# Поиск по репозиторию и исходникам 1С

Этот регламент — проектный поисковый регламент, на который ссылается раздел `Search Playbook` в `AGENTS.md`. Он уточняет порядок из `Search Playbook` для исходников 1С и не отменяет его: порядок «семантический поиск → `rg` → `rg --files` → прямое чтение», узкий первый проход и подтверждение в двух источниках сохраняются. Если проект добавил собственный регламент поиска, приоритет у него.

Индексы помогают найти доказательство, но не заменяют чтение исходника, тест или наблюдение в точной ИБ.

## 1. Индексы и их области

| Индекс | Корень | Что в нём искать |
| --- | --- | --- |
| Семантический индекс репозитория (`mcp__claude-context__search_code` или `ast-index`) | корень репозитория с исключением `src/**` | документация, OpenSpec, сценарии, обёртки, тесты, навыки |
| Семантический индекс исходников конфигурации | точный корень выгрузки, например `src/cf` | процедуры, модули и формы основной конфигурации |
| Семантический индекс исходников расширения | точный корень расширения, например `src/cfe/<Расширение>` | модули и заимствованные объекты расширения |
| Семантический индекс внешних обработок и отчётов | точный корень выгрузки в `src/epf` или `src/erf` | модули EPF/ERF |
| `bsl-analyzer-workspace` (MCP) | исходники, выбранные при запуске `make bsl-analyzer-mcp` | `search`, `symbol_info`, `graph`, `metadata`, `diagnostics`; живые запросы к ИБ по `connection` |

Правила:

- Процедуру или модуль конфигурации ищите в индексе точного корня этой конфигурации, а не в индексе корня репозитория. Индекс корня репозитория исходники `src/**` не содержит.
- Не смешивайте корни: результат из соседней конфигурации или расширения не отвечает на вопрос о целевой.
- Не создавайте новый индекс на каждую сессию и не перестраивайте готовый индекс без доказанного рассогласования. Состояние `loading` означает «повторить после готовности», а не «данных нет».
- `rlm-tools` допустим только как вспомогательное исследование по `Search Playbook`; его вывод не является доказательством.

## 2. Определить вид факта

| Искомый факт | Первый инструмент | Чем подтвердить |
| --- | --- | --- |
| Документация, OpenSpec, сценарий или обёртка | семантический индекс репозитория | точный файл и связанная проверка |
| Неизвестное место реализации в BSL | семантический индекс точного корня или `search(action=search_code)` | прямое чтение найденного `.bsl` |
| Известный символ, сигнатура или тип | `symbol_info` | определение и при необходимости места использования |
| Вызовы и влияние изменения | `graph` | исходники вызывающего и вызываемого символов |
| Состав объекта или управляемой формы | `metadata` в режиме `source` | карточка метаданных и исходный файл при спорном поле |
| Ошибка синтаксиса или статического анализа | `diagnostics`, навык `1c-check-bsl` | точный диапазон исходника и минимальное воспроизведение |
| Фактические метаданные или данные ИБ | `metadata`/`query` с точным `connection` | ответ той же ИБ |
| Реальное выполнение | `event_log` или `debug` с точной ИБ | идентификатор запуска, наблюдаемая ветка, состояние до и после |
| Поведение платформы | официальная документация 1С | версия платформы, режим совместимости, контекст выполнения |

Не смешивайте эти утверждения. Найденный исходник не доказывает, что он загружен или выполнен в ИБ; живой объект не доказывает, что локальная выгрузка ему соответствует; пустой результат индекса не доказывает отсутствие объекта.

## 3. Порядок поиска

1. **Семантический поиск** в индексе нужной области (раздел 1).
   - Формулируйте запрос как «компонент + действие + контекст», например `документ поступления проведение по регистру взаиморасчётов`.
   - Первый проход — 6–10 результатов.
   - Сразу оставляйте результаты только из точного корня.
   - Шумную выдачу сужайте именем объекта или метода, а не расширением выдачи.
2. **`rg`** по уже известному имени символа, объекта или строки. Ограничивайте область точным корнем и расширением (`--glob '*.bsl'`). Параметры `rg`, включая `--glob`, указывайте до маркера `--`; после него — только шаблон и пути.
3. **`rg --files`** — если нужно найти файл по имени объекта или пути выгрузки.
4. **Прямое чтение** найденных файлов. Большие XML читайте по диапазонам или через `metadata`.

Широкий `rg` по крупной выгрузке — последний навигационный шаг, а не первый.

## 4. Известный символ и связи

- Начинайте с одного `symbol_info` по квалифицированному имени. Для локальной переменной передавайте точные `path` и `line`. Если вернулось несколько кандидатов, выберите по корню и виду символа; не берите первый результат наугад.
- Полный список связей получайте через `graph(callers|callees)`. Поле `usages` карточки символа — краткая сводка, а не полный перечень.
- Читайте тела только тех узлов, которые участвуют в доказываемой ветке. Перед изменением общей функции проверьте её другие вызовы: исправление в общем слое предпочтительнее одинаковых поправок в вызывающих местах.
- После изменения проверьте затронутые модули навыком `1c-check-bsl`.

## 5. Метаданные и формы

Для перечня и структуры используйте `metadata(tree|object|form)` вместо чтения больших XML. Прямое чтение XML остаётся запасным доказательством для полей, которых нет в карточке, двоичных макетов, обычных форм, MXL и других неиндексируемых частей выгрузки.

В режиме `infobase` всегда передавайте точный `connection`. Техническое имя типа не восстанавливайте по пользовательскому представлению: неоднозначность фиксируйте как ограничение.

## 6. Живое доказательство

Переходите к живой проверке, только когда вывод относится к данным, загруженной конфигурации или выполненной ветке:

- `metadata(mode=infobase)` — фактический состав ИБ;
- `query(validate)` — корректность запроса относительно схемы;
- `query(execute)` — данные, только с точным `connection` и ограничением числа строк;
- `execute(check)` — проверка BSL через разрешённую ИБ;
- `event_log` — наблюдаемая ветка с устойчивым событием и идентификатором запуска;
- `debug` — пошаговое исследование, когда журнал не отвечает на вопрос.

`run` и `eval` используйте только в явно разрешённой расходуемой базе. Секреты и лишние хозяйственные данные в доказательства не включайте.

## 7. Подтвердить вывод

Для каждого существенного вывода укажите:

- точный корень исходников или имя подключения;
- найденный символ или объект;
- исходный файл;
- второе доказательство: тест, спецификацию, карточку метаданных или живой ответ;
- ограничения: состояние индекса, усечение, неоднозначность, версия платформы и режим совместимости.

Файлы задач, чек-листы и статусы не доказывают реализацию. При пустом или частичном результате проверьте готовность индекса, область и точное имя, затем перейдите к следующему шагу порядка из раздела 3.
