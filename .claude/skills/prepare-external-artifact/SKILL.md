# Подготовка внешнего артефакта

Repo script: `./scripts/python/ordinary_form_conversion.py`

Использовать существующую команду репозитория; не дублировать её логику отдельным сценарием навыка.

## Порядок работы

1. Работать из корня репозитория и прочитать `docs/agent/ordinary-form-conversion-runbook.md`.
2. Для EPF запустить:

```powershell
python -m scripts.python.cli ordinary-form-conversion prepare-sources --input <вход.epf> --profile <профиль.json>
```

Команда публикует `src/epf/ordinary/<Имя>/` и `src/epf/managed/<Имя>/`, возвращает `agent-remediation-required` и останавливается. Не передавать `--output` или `--run-root`.

3. Для ERF или поддерживаемого дерева v8unpack проверить новый выходной путь вне `src/**` и запустить прежний маршрут:

```powershell
python -m scripts.python.cli ordinary-form-conversion prepare --input <вход.erf|дерево-v8unpack> --profile <профиль.json> --output <новый-пакет>
```

4. Для EPF прочитать новую `.artifacts/ordinary-form-conversion/<run-id>/preparation-summary.json`; для прежнего маршрута — `<новый-пакет>/preparation-summary.json`.
5. Следовать только полю `nextAction`:
   - `resolve-structure` — устранить структурные разрывы по `<новый-пакет>/managed/conversion-report.json`;
   - `adapt-bsl` — передать модули из `modules` на отдельную агентскую адаптацию; проверить вызовный путь форма → объект: реквизиты и табличные части основного объекта квалифицировать через `ОбработкаОбъект`, прямой вызов экспортной функции объекта перенести в минимальную серверную функцию через `ОбработкаОбъект`, показ результата оставить на клиенте, а клиентские диалоги из серверных модулей заменить по смыслу на результат либо содержательное исключение. Реквизиты самой формы оставлять без этого префикса. До последующей сборки сопоставить с обычной формой порядок элементов внутри каждой страницы, явные заголовки команд, колонок и секций; пару дат с отдельной кнопкой периода заменять на `СтандартныйПериод`; у внешней командной панели сохранять исходный порядок и пользовательские заголовки; поле рядом с командной панелью помещать вместе с ней в горизонтальную группу, но не внутрь `CommandBar`; одностраничную служебную панель без переключения страниц переносить как группу. Если обычная форма показывает многораздельную пользовательскую панель рядом с результатом, сохранять её отдельной соседней областью: не переносить под результат, не заменять одной строкой вкладок и не выносить команды секций в корень формы. Наличие каждого дочернего элемента и принадлежность его командной панели проверять до сборки. Неоднозначно привязанные к странице или данным элементы размещать вручную, не добавляя эвристику конвертера и не считая частичный перенос успешным. В модуле объекта сохранить либо добавить `СведенияОВнешнейОбработке` с регистрационными сведениями по фактическому API целевой БСП. Фактический вид проверяет оператор отдельно; без этой проверки допустима передача собранного кандидата, но не статус `ready`.
6. Сначала различить контейнер и геометрический разделитель обычной формы. Группу-разделитель с явным заголовком и без дочерних элементов переносить как самостоятельную надпись, а не как пустую группу. Для настоящей группы-контейнера с явным пользовательским заголовком включить `ОтображатьЗаголовок`; для контейнера без явного заголовка оставить его выключенным. Главное действие обычной формы сохранять как кнопку по умолчанию, когда оно определяется однозначно.
7. Перед сборкой из канонического `src/**/managed` сверить, что принятые исправления формы из рабочего пакета перенесены именно в этот источник сборки; наличие исправления только в пакете не считать исправлением кандидата.

## Границы

- Не направлять EPF в `publish-sources`: этот старый маршрут запрещён для семейства EPF.
- Не перезаписывать существующий output и не перемещать пакет в `src/**` автоматически.
- Не выполнять в рамках этого навыка адаптацию BSL, `verify-remediation`, проверку синтаксиса, сборку, публикацию, запуск 1С, live-проверку или `ready`.
- Синтаксис адаптированных модулей проверяется после навыка по [регламенту конвертации](../../../docs/agent/ordinary-form-conversion-runbook.md): только `bsl-analyzer` с точным подключением целевой ИБ. Проверку модулей EPF/ERF как части рабочей области основной конфигурации не засчитывать.
- Не считать `agent-remediation-required` или `structure-remediation-required` готовностью EPF/ERF.
- При ошибке сообщить путь редактированного evidence из диагностики; не удалять его до разбора причины.
