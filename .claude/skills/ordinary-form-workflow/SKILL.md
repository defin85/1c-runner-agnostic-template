# Полный цикл обычной формы

Repo script: `./scripts/skills/run-imported-skill.sh`

Этот навык координирует этапы, а команды и ограничения берёт из специализированных навыков. Не копировать сюда их реализацию и не создавать второй сборщик.

## Маршрутизация

Открывать навыки по точным путям текущего каталога Available skills; отсутствующий искать в разрешённом каталоге навыков. Не угадывать skill root. `v8unpack` также доступен рядом: [../v8unpack/SKILL.md](../v8unpack/SKILL.md).

| Этап | Навык |
| --- | --- |
| Выгрузка EPF / ERF через Designer | `epf-dump` / `erf-dump` |
| Распаковка, правка и упаковка Form.bin | `v8unpack` |
| Стандарты и совместимость изменяемого BSL | `1c-guidance` |
| Анализ и платформенная проверка BSL в доступном точном контуре | `make analyze-bsl` или проектный навык проверки BSL |
| Структурная проверка метаданных при их изменении | `epf-validate` / `erf-validate` |
| Сборка EPF / ERF через Designer | `epf-build` / `erf-build` |
| Явная диагностика упаковки при необходимости | `epf-dump` / `erf-dump` |

Зависимости `epf-*`, `erf-*` и проверка BSL могут быть проектными. Если нужной нет, определить доступную штатную обёртку; при отсутствии сообщить, какой этап недоступен. Не устанавливать произвольную замену и не объявлять полный цикл завершённым.

## Выполнение

1. Определить вход (бинарный EPF/ERF или готовая Designer-выгрузка), нужную форму, правку и ожидаемый результат. Проверить фактическую платформу, конфигурацию и режим совместимости целевого контура. Для ограниченного запроса «только собрать» выполнять только требуемые этапы и контроль результата.
2. Подготовить отдельную рабочую копию. Если дан бинарник — выгрузить соответствующим `*-dump`. Использовать базу с нужными метаданными: пустая ИБ может потерять ссылочные типы. Исходную выгрузку повторно не получать без причины.
3. Через `v8unpack` распаковать только затронутые `Forms/<Имя>/Ext/Form.bin`. Изучить модуль и связанные элементы до правки. Изменения модуля объекта делать в его `.bsl`, не перепаковывая незатронутые формы.
4. Выполнить правки и узкие проверки. Для BSL применять `1c-guidance` и доступные проверки BSL из таблицы выше. Сборка контейнера не проверяет семантику BSL. Не выдавать проверку основной конфигурации за проверку внешней обработки, если её модули туда не входят.
5. Через `v8unpack` собрать Form.bin, проверить содержимое и поместить результат только в соответствующий путь рабочей Designer-выгрузки. Сохранить остальные формы, метаданные и ресурсы.
6. Через соответствующий `*-build` собрать новый EPF/ERF. На Linux использовать предусмотренный проектом путь Designer под Xpra. Перед длительным этапом определить штатные progress/log и terminal result; не подменять их ожиданием большого timeout. Не раскрывать параметры авторизации.
7. Обычную сборку завершать без контрольной обратной выгрузки. При изменении упаковщика либо диагностике конкретной потери содержимого отдельно вызвать `*-dump`, распаковать затронутую форму через `v8unpack` и сопоставить ожидаемые модули и описание формы. Не требовать равенства SHA всего EPF/Form.bin после нормализации платформой.
8. Для запроса на работающую доработку выполнить проверку изменённого поведения в разрешённой тестовой ИБ. Сборка и контрольная выгрузка не заменяют проверку открытия формы, обработчиков и бизнес-логики. Запуск обработки с изменением данных требует авторизованного расходуемого контура; запрос на сборку сам по себе его не разрешает.

Вернуть путь EPF/ERF, что именно проверено (контейнер, Designer, BSL, поведение), и оставшиеся ограничения. Перенос правок из рабочей копии в исходники, commit/push выполнять в границах задачи и правил проекта.

## Наблюдение платформенного запуска

При запуске платформы использовать [1c-observe-run](../1c-observe-run/SKILL.md):
курсоры журналов клиента и сервера, подтверждение точного PID и итоговое
дочитывание журналов. Сборка или пустой техжурнал не заменяют проверку целевого сценария.
