# Agent Skill: site-rdp-bash-payload

Repo script: `./scripts/site/site-operator.sh`

## Use When

- Пользователь сам вводит команды в RDP-shell площадки, а агент готовит их.
- Команда содержит кавычки, циклы, подстановки или требует `sudo`.

## Порядок

1. Прочитайте [правила площадки](../../../docs/infra/site/rules.md); отделите
   диагностику без изменений от изменяющей операции.
2. Запишите исходную команду одной строкой во временный файл, например
   `/tmp/site-task.payload`.
3. Проверьте её без буфера обмена:

   ```bash
   ./scripts/site/site-operator.sh payload --check --file /tmp/site-task.payload
   ```

4. Перед первым `sudo` подготовьте проверку права:

   ```bash
   ./scripts/site/site-operator.sh payload --sudo-check --file /tmp/site-task.payload
   ```

   Пользователь вставляет команду, сверяет и нажимает Enter. Продолжайте только
   после `sudo_payload_check_rc=0`.
5. Положите в буфер ту же команду:

   ```bash
   ./scripts/site/site-operator.sh payload --file /tmp/site-task.payload
   ```

   Для одной команды без root используйте `--no-sudo`: она передаётся как есть,
   без `bash -c`. На хосте с X11 вместо Wayland добавьте `--clipboard x11`.

## Ограничения

- Команда непустая, только печатные ASCII-символы, без переводов строки;
  итоговая длина — до 4096 символов. `command_too_long` означает, что операцию
  нужно разделить.
- Запрещены отдельные `exit`, `logout` и `exec`: они закрывают удалённый shell.
- `set -euo pipefail` добавляется только внутри отдельного `bash -c`, не в
  интерактивный shell.
- Не включайте пароли, PIN, токены, приватные URL и содержимое лицензий.
- Изменяющую команду готовьте только после явного разрешения пользователя:
  успешная проверка `sudo` подтверждает право, но не разрешает изменение.
- Файлы переносите через `transfer` навыка `site-vdi-xpra`.
