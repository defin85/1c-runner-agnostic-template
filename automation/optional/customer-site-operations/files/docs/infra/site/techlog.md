# `site-techlog-control`: технологический журнал сервера приложений

Включает ограниченный технологический журнал для диагностики лицензий и
ожиданий управляемых блокировок. Запуск на сервере приложений; права `root`
нужны, чтобы назначить владельцем каталогов журнала пользователя службы 1С.

| Команда | Что делает |
|---|---|
| `start` | пишет `logcfg.xml` с событиями `lic`, `hasp`, `excp` в `techlog.log_dir` |
| `status` | состояние, владение `logcfg.xml`, число и размер файлов журнала |
| `stop` | удаляет свой `logcfg.xml`; журналы сохраняются |
| `locks-start` | добавляет отдельный журнал `tlock` (только ожидания), `ttimeout`, `tdeadlock` |
| `locks-stop` | возвращает состояние до `locks-start` |
| `locks-report [--minutes N]` | агрегирует ожидания блокировок по областям: число, суммарное время, один укороченный пример ключа |

## Правила

- Обёртка меняет `logcfg.xml` только если его нет или он совпадает с копией,
  которую установила она сама (`techlog.state_dir`). Иначе — `conflict`, и файл
  не меняется: чужую настройку журнала разбирайте отдельно.
- Сервер 1С перечитывает `logcfg.xml` в течение минуты.
- Перед включением обёртка проверяет запас места (`techlog.min_free_mib`).
  `history="1"` ограничивает журнал одним часом.
- Отчёт выводит только агрегаты: технологический журнал содержит многострочные
  события с данными, их не выводите наружу целиком.
- Журнал запуска клиента при локальной диагностике — отдельный инструмент
  шаблона `scripts/diag/technological-log.sh`.
