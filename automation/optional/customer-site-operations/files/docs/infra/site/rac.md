# `site-rac`: операции кластера через RAS

Запуск на сервере приложений (`app_host` профиля). Обёртка выбирает базу по
точному имени, читает UUID кластера, путь `rac` и адрес RAS из профиля и
не выводит пароли.

## Команды

| Команда | Что делает | Меняет состояние |
|---|---|---|
| `list` | имена и UUID зарегистрированных баз | нет |
| `info BASE` | привязка к СУБД, запрет входа, запрет заданий, выдача лицензий | нет |
| `sessions BASE` | сеансы базы (идентификаторы и приложение) | нет |
| `perf BASE [--sample SEC]` | загрузка сеансов за интервал: доли СУБД, служб кластера, CPU | нет |
| `lock BASE` / `unlock BASE` | включает или снимает запрет входа | да |
| `jobs-off BASE` / `jobs-on BASE` | запрещает или разрешает регламентные задания | да |
| `license-on BASE` | разрешает выдачу клиентских лицензий сервером | да |
| `unregister BASE --confirm 'UNREGISTER BASE'` | удаляет регистрацию disposable-копии | да |

Примеры:

```bash
python3 /opt/site-ops/site-rac info app_main
python3 /opt/site-ops/site-rac jobs-off app_main
```

## Правила

- Изменяющие команды работают только для баз из раздела `infobases` профиля.
  Для другой базы обёртка завершается `REFUSED:` до обращения к кластеру.
- `unregister` разрешён только для базы с `"disposable": true`, без сеансов и
  с запрещёнными заданиями. Данные в СУБД он не удаляет — для этого
  `site-golden-db discard-copy` на сервере СУБД (см. [ibcmd.md](ibcmd.md)).
- Каждая изменяющая команда проверяет результат: нужный флаг установлен, второй
  флаг (вход или задания) не изменился. Если нужное состояние уже есть,
  изменения нет.
- `lock` не завершает сеансы. Завершение чужих сеансов и перезапуск служб
  согласуйте отдельно.
- Выдача лицензий (`license-on`) — настройка, а не доказательство наличия
  лицензии.
- `--auth-base OTHER` разрешён только для read-only команд: учётные данные
  берутся у другой базы из профиля.
- Код возврата 255 от `rac` не доказывает ошибку аутентификации: не меняйте
  пароль и его источник только из-за него.

## Доработка

Если обёртке не хватает поля или команды, добавьте минимальную возможность в
`infra/site/server/site-rac` проекта и тест к ней. Длинные одноразовые прямые
вызовы `rac` не закрепляйте как обычный способ работы. Для дополнительного
поля предпочитайте расширение `info`.
