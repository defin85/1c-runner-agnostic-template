# `site-license-request`: офлайн-запрос программной лицензии

Готовит файл запроса на активацию или восстановление программной лицензии 1С
утилитой `ring license prepare-request` без обращения к центру
лицензирования. Запуск от `root` на сервере, где будет активирована лицензия.

## Данные

В каталоге `license.base_dir` (владелец `root`, права 0700) лежат два файла
`root:root 0600`:

- `recovery-pins.env` — `SERVER_PREVIOUS_PIN`, `SERVER_NEW_PIN` и при
  необходимости `CLIENT_PREVIOUS_PIN`, `CLIENT_NEW_PIN`;
- `owner-data.env` — `COMPANY`, `COUNTRY`, `ZIP_CODE`, `TOWN`, `STREET`,
  `HOUSE`, `REGISTRATION_NUMBER`, `EMAIL`, необязательно `FIRST_NAME`,
  `MIDDLE_NAME`, `LAST_NAME`.

Формат строк — `KEY=value`. Значения вносит ответственный сотрудник заказчика;
агент их не запрашивает, не выводит и не копирует.

## Команды

```bash
python3 /opt/site-ops/site-license-request check --kind server
python3 /opt/site-ops/site-license-request prepare --kind server [--download-copy]
```

- `check` проверяет права файлов, наличие и формат полей, различие нового и
  прежнего PIN. Вывод — только `valid` или причина без значений.
- `prepare` создаёт новый каталог `offline-request-<время>-*` в `license.base_dir`
  с файлом запроса и журналом `ring` (оба 0600). `--download-copy` дополнительно
  кладёт копию запроса с правами 0644 в `/tmp` для переноса оператором и сверяет
  её SHA-256 с исходным файлом.
- При ошибке `ring` выводится код и путь к защищённому журналу; сам журнал не
  выводится.

## Правила

- Не начинайте лицензирование без официального источника лицензии и
  утверждённой процедуры заказчика.
- Файл запроса и файл ответа — секретные данные: не помещайте их в Git,
  документы и журналы.
- Наличие `.lic` не доказывает исправность лицензии: критерий — серверная
  операция и вход клиента без ошибки лицензирования.
