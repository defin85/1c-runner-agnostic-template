# `site-db-archive`: архивирование прочих баз PostgreSQL

Освобождает место на сервере СУБД: база сохраняется в проверенный архив и
только после пробного восстановления удаляется. Запуск от `root` на сервере
СУБД (`db_host` профиля), PostgreSQL 15 и новее.

## Что можно архивировать

- Только базы из `archive.databases` профиля.
- Никогда: `postgres`, `template0`, `template1`, любые базы из `infobases` и
  `golden.bases` профиля, временные копии с префиксом `site_archive_`.
- Только базы владельца `postgres` с провайдером libc в `pg_default`, без
  особых ACL, настроек, меток безопасности, внешних таблиц и подписок.

## Этапы

Каждый изменяющий этап требует `--confirm '<ДЕЙСТВИЕ> <база или операция>'`.

| Команда | Что делает |
|---|---|
| `plan --database D` | размер базы, свободное место, требуемый запас; ничего не меняет |
| `archive --database D --confirm 'ARCHIVE D'` | закрывает вход в базу, делает её физическую копию, снимает отпечаток данных и схемы, пишет архив `pg_dump` из копии, удаляет копию |
| `verify-restore --database D` | восстанавливает архив во временную базу, сверяет отпечаток данных и схемы, удаляет временную базу |
| `drop-source --database D --confirm 'DROP-SOURCE D'` | удаляет исходную базу только после успешного `verify-restore` |
| `status --database D` | состояние операции |
| `cancel --database D --confirm 'CANCEL D'` | отменяет операцию до удаления и снова открывает вход |
| `restore-source --database D --confirm 'RESTORE-SOURCE D'` | возвращает удалённую базу из архива с закрытым входом |
| `reopen --database D --confirm 'REOPEN D'` | открывает вход в возвращённую базу |
| `cleanup-temp`, `reconcile` | разбор прерванной операции |

`--jobs 1..4` задаёт число потоков `pg_dump` и `pg_restore`
(по умолчанию `archive.jobs`). При `--jobs` больше 1 архив хранится в формате
directory.

## Границы

- Отпечаток — хеши строк всех таблиц, последовательностей, больших объектов,
  колонок и индексов. Это не побайтное сравнение файлов, но оно не выводит
  данные заказчика в журналы.
- Запас места: 4 ГиБ сверх двойного размера базы на диске архива и на диске
  данных PostgreSQL. Во время длинных шагов обёртка проверяет запас и
  останавливает инструмент при его исчерпании.
- Одна операция на хранилище; незавершённая операция блокирует новые.

## Ошибка или прерывание

1. `status` показывает этап и временную базу, если она осталась.
2. `cleanup-temp` удаляет только временную базу этой операции, сверив её OID.
3. `reconcile` завершает поддерживаемые прерванные переходы (архив записан,
   удаление начато, переименование при возврате начато).
4. Если `reconcile` отказывает — разбирайте вручную, ничего не удаляя.
