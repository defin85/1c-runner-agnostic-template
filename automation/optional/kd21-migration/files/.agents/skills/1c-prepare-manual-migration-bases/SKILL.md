# Подготовка баз для ручной проверки миграции

Repo script: `./scripts/migration/kd-rules-cycle`
Windows launcher: `./scripts/migration/kd-rules-cycle.ps1`

Используйте только для расходуемых баз из `workbases` профиля `migration/kd21/profiles/local.json`. Эталонные базы (`references`) не изменяются. Навык вызывает существующие команды исполнителя и не добавляет новых точек запуска.

## Перед запуском

1. Прочитайте `docs/agent/kd21-rules-workbench-runbook.md`.
2. Покажите `git status --short`; не меняйте и не коммитьте рабочее дерево.
3. Выполните `doctor` в новом абсолютном `run-root` вне репозитория и убедитесь, что он прошёл.

## Порядок подготовки

Автоматическая приёмка и ручная проверка используют разные поколения баз.

### 1. Автоматическая приёмка

Выполните полный прогон сценария в новом `run-root`:

```bash
./scripts/migration/kd-rules-cycle --profile migration/kd21/profiles/local.json \
  --scenario migration/kd21/scenarios/<сценарий> --run-root "$acceptance_root" all
```

Принимайте только `result.json.status = workbench-run-passed` и наличие `release.manifestSha256`. Сохраните путь к этому `result.json`.

### 2. Финальное поколение баз

В другом новом `run-root` выполните `doctor`, затем `reset`. `reset` восстанавливает обе расходуемые базы из golden-снимков эталонов и записывает новое поколение в `result.json.generations`. Если ручной проверке нужны прикладные узлы сценария (например, установка расширения), выполните их командой `run <узел>` после `build` и `load`, а не вручную.

### 3. Тождественность опубликованных правил

Выполните `run build-rules` в отдельном новом `run-root` и сравните `files` и `archives` опубликованного `manifest.json` в `releasePublishRoot` с манифестом выпуска автоматической приёмки. При любом отличии базы оператору не передавайте: разберите причину по регламенту.

## Наблюдение

- Во время долгих стадий читайте `<run-root>/progress.txt` и `observation.jsonl` стадии; сообщайте стадию и возраст прогресса. При зависании используйте навык `1c-observe-run`.
- После завершения с ошибкой не переиспользуйте `run-root`.

## Граница готовности

После финального `reset` не запускайте в этом поколении стадии и узлы, которые меняют данные баз. В итоговом сообщении укажите имена двух баз, путь к опубликованным правилам, `result.json` автоматической приёмки и `result.json` финального поколения.
